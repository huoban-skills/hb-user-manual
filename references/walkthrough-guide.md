# 浏览器走查规范

走查的目标是两个：拿到文档配图，拿到界面实测细节。前提是本单元的摘要包（digest.py 输出）或用户提供的流程已在手，走查是按图索骥不是瞎逛。

---

## 一、截图点位清单

动手前先从元数据推导每章的点位清单，列出来对着执行。每张主表的标准点位：

| 点位 | 截图内容 | 截法 |
|------|----------|------|
| 列表页 | 表的默认视图，含视图切换和新建按钮 | 整页，新建按钮标红框 |
| 新建表单 | 点新建后的表单页，必填标记可见 | 整页或表单容器局部图 |
| 详情页 | 一条记录的详情，**含滚到底才看得到的子表页签、关联记录区** | 整页，长页面分屏截 |
| 首页/工作台 | 顶部指标和入口 + **每个跟踪页签** + **下半屏的筛选区、清单区** | 分屏截，每屏一张 |
| 每个写进手册的按钮 | ① 按钮位置 ② 点击后的弹窗/表单/结果 | ① 整页+红框 ② 弹窗局部图 |
| 审批入口（如有） | 提交后的审批状态展示 | 局部图 |
| 显隐字段（如有） | 触发条件满足后字段出现的样子 | 表单局部图 |

不是每个点位都必须成图入册：一步一图不强求，一个操作序列至少要有**入口图（在哪点）、过程图（填什么/弹什么）、结果图（系统给了什么反馈）**三类，能合并的合并。

## 二、操作节奏

每一步都走「看 → 动 → 看 → 截」：

```bash
python3 scripts/browser.py goto --url <页面>
python3 scripts/browser.py snapshot                 # 确认页面对、加载完
python3 scripts/browser.py click --text "新建"
python3 scripts/browser.py snapshot                 # 确认弹出的是预期表单
python3 scripts/browser.py shot --path images/2-1-新建订单表单.png
```

- **不盲截**：每次操作后先 snapshot 看结果，页面不对就别截。
- SPA 内容没渲染出来用 `wait --text` / `wait --selector`，不要用截图试错。
- 弹窗、抽屉、下拉面板用 `shot --selector <容器>` 截局部图；找容器 selector 可用 `eval` 探。
- 点击优先 `--text`（按钮文字），文字重复时 snapshot 拿编号用 `--index`。
- **控制台类 SPA（阿里云、腾讯云等）改用 `click --at` 坐标点击。** 这类页面 class 是随机哈希、snapshot 的元素编号每次重渲染都会变，`--text` / `--index` 经常落空。做法是先 `shot` 存盘、读回来看、从图上量出位置再点。
- **坐标要除以 2**：截图是 2 倍图（如 2880×1600），`click --at` 收的是 CSS 像素（1440×800）。中间再夹一个缩略图尺寸更容易算错，量完先换算再点。
- 截图前确认当前 URL 和页面状态，别让上一次点击的残留页面混进来。

## 三、每个页面都要看全

进入新页面（含弹窗、抽屉）先看全再写：**纵向翻到底，横向每个页签点开**。首屏信息量不是停止条件，翻到底才是。伙伴云的工作台、详情页普遍比一屏长，筛选区、子表页签、行内按钮常在下半屏。

**页签**：

- 先 snapshot 把页签名列全，逐个点开看过再写；页签名不等于页签内容，没点开的不写。
- 内容差异大的分别截图；同构的截一张代表图，正文说明其余同理。
- 点页签用 `--text "<页签名>"`，点完 snapshot 确认高亮落在预期页签。

**纵向**：

```bash
# 1. 列出可滚动容器（伙伴云是嵌套滚动，scrollHeight 远大于 clientHeight 说明底下压着内容）
python3 scripts/browser.py eval --js "(()=>{const e=[...document.querySelectorAll('div')].filter(x=>x.scrollHeight>x.clientHeight+50&&x.clientHeight>300);return e.map(x=>x.className.slice(0,40)+' | '+x.clientHeight+'/'+x.scrollHeight)})()"

# 2. 全部滚到底（中段把 scrollHeight 换成 scrollHeight*0.45 等比例）
python3 scripts/browser.py eval --js "(()=>{const e=[...document.querySelectorAll('div')].filter(x=>x.scrollHeight>x.clientHeight+50&&x.clientHeight>300);e.forEach(x=>x.scrollTop=x.scrollHeight);return 1})()"
python3 scripts/browser.py shot --path <scratch>/probe-bottom.png
```

- `scroll --dy` 对伙伴云主内容区常常无效，直接用上面的 `eval` 设 `scrollTop`。
- 探查图落 scratchpad，确认有内容再重截正式配图；长页面拆两三张图入册。
- 宽度同理：子表有横向滚动条时右侧还压着关键状态列，拖到底看全再写。

## 四、截图一致性

- **窗口尺寸不用管**：驱动脚本每条命令自动把窗口铺满它所在的屏幕（换屏拖过去即可）；视口小于 1440×800 时才用 CDP 放大兜底。固定尺寸用 `HB_WIN=2560x1440 python3 scripts/browser.py start` 指定。
- 判断截图够不够大看 `eval --js "[innerWidth,innerHeight]"`，不看窗口外观。
- 不开开发者工具，同一册截图用同一尺寸。
- 红框（`--highlight`）只标当前步骤的要点，一张图不超过 2 个红框。
- 同一章的截图在同一次走查里完成，避免界面前后状态不一致。

## 五、标注：红框与脱敏

`shot --highlight` / `--blur` / `--mask` 靠 CSS selector，控制台类 SPA 的随机 class 匹配不上，这时用 `scripts/annotate.py` 按百分比坐标处理。

```bash
python3 scripts/annotate.py <图> --crop 10,75 --grid              # 先量
python3 scripts/annotate.py <图> --crop 10,75 --box 14,36,73,44 --blur 10,20,45,28 --fill 85,0,100,7
```

- **位置要量不要估。** 先用 `--grid` 叠一层百分比网格读坐标，凭肉眼估比例基本每次都偏。没量过就画框脚本会直接报错拦下。
- **`--grid` 和画框要用同一个 `--crop`。** 所有百分比都相对裁剪后的成图，量到什么填什么；裁剪一变坐标全错位，脚本会拦。
- 脚本会自动把原图备份成 `<图名>.orig.png`，标错了能重来。交付前连同 `.grid.png` 一起清掉。
- 姓名、手机号、邮箱、企业名称、订单号、UID、实例地址等普通敏感文字默认用 `--blur`；只模糊值，不盖住字段名、列名和表单结构。模糊后按原尺寸复看，字符必须不可辨认，但字段行数、长度和界面布局仍可理解。
- 模糊框必须贴合敏感字符本身，只在文字外沿留极小余量；禁止直接框整个输入框、整格单元格或整行表单。一个列表里有多条敏感值时逐条画多个小框，宁可多写几个 `--blur`，也不能合并成大块。
- 单行字段按“字符带”框选：纵向只覆盖字形高度，不覆盖输入框的整行高度；横向只到最后一个敏感字符，不顺手延伸到空白区。空值不需要打码。
- 多行文本按屏幕上实际渲染的行逐行拆开，每一行一个窄 `--blur`；不能用一个矩形包住整个文本框。相邻列、相邻记录即使距离很近也分别框选。
- 选区上边界必须位于字段名或列名下方，并留出肉眼可见的清晰间隔。系统字段文字的任意笔画一旦进入模糊区，就视为不合格，需要回到原图缩小或下移选区。
- 能通过裁剪去掉无关真实数据时先裁剪，再对仍需保留的敏感字符做最小范围模糊。字段名、列名、提示文案、输入框边界和按钮不参与模糊。
- 密钥、令牌、密码、Cookie、签名值、Webhook 地址等可直接授权访问的秘密不能只做模糊，必须用 `--fill` 不可逆遮挡。
- 地域、产品名、规格等教学所需信息不要脱敏，它们正是读者要核对的内容。
- 如果一张图需要模糊大半个表单，优先换成演示数据重截；只有无法重截时才对多个值分别模糊，禁止用一个大色块覆盖整片字段。
- 交付前按原始尺寸放大复看两遍：第一遍确认任何敏感字符都读不出，第二遍确认每个系统字段名和操作入口都仍能读清。若只在下沿或末尾漏出笔画，只向下或向末尾补极小选区；不得向字段名方向扩张，也不得把原有多个小框合并成一块。修改后必须重新执行两遍复检。

### 最小选区操作法

1. 用 `--grid` 量出字段名、值和输入框边界，先确定字段名的禁入区域。
2. 给每个值建立独立选区：短值一个字符带，长值按实际行拆分；选区之间保留原有空白和结构线。
3. 先用适中强度模糊并查看原尺寸成图。模糊半径只决定字符是否可辨，不决定选区范围。
4. 有漏字时沿字形的下沿或末端小幅补齐；有系统文字受影响时立即从原图重做并缩小对应选区。
5. 无法在不遮挡字段名的情况下安全模糊时，换演示数据重截，不用扩大遮挡范围解决。

## 六、演示数据

- 走查需要落数据就直接创建，标题带「演示-」前缀（如「演示-销售订单0810」）。
- 每落一条登记进 `demo-data.md`：表名、记录标题、创建入口。截图尽量用演示数据入图，避免真实客户敏感信息。
- 完稿自检后统一删除：界面删除或 `hac table batch-delete-items`，删到回收站即可，不做彻底删除。

## 七、实测笔记 notes.md

每个点位走完记一条，格式：

```
### 2-1 新建销售订单
- 页面：销售订单列表 → 新建
- 操作：点「新建」，填客户、明细，保存
- 观察：保存时弹「客户不能为空」原文提示；订单编号保存后自动生成 DD20260810001；
  「优惠金额」在选了「特价订单」后才出现
- 截图：2-1-新建订单表单.png、2-2-保存校验提示.png
```

- 系统提示文案记**原文**，写手册时直接引用，不转述。
- 界面实测和 hac 配置对不上时（如配置里有的字段界面没显示），以界面为准写手册，并在笔记里标记差异，交付时向用户提一句。
- 界面异常（「字段不存在」、图表报错、按钮无反应）是演示环境缺陷：不写进手册，记进笔记，交付时逐条报给用户去修。
- 工作台/首页清单常带默认过滤（如只显示当前登录人的数据）且界面不写明：条数和主表对不上时用 `hac table list-items --columns` 按可疑字段统计核实，查实的口径写进该章注意事项。

## 八、配置类场景

文档教读者怎么配置某功能（自动化、提醒、视图、对接等）时，AI 不动手做配置，只对已搭好的演示环境做只读走查：

- 走查前先和用户确认演示环境里该配置是否已搭好；没搭好就停下来让用户搭，不代搭。
- 已搭好的：逐步进入配置入口和各级配置页，按读者第一次配置的路径截图（入口 → 配置面板各步 → 保存后的状态）。
- 可以打开新建/编辑面板截取表单形态的图，但**不保存、不提交、不改动任何已有配置**。
- 步骤文字仍按读者第一次配置的视角写（"点「新建提醒」，选择日期字段…"），图用已配好的环境截。

## 九、跨平台走查

流程涉及伙伴云以外的平台（企微、钉钉、飞书、第三方系统等）时：

- 驱动脚本直接 `goto` 外部平台，登录态同样存在持久化 profile，外部平台首次也由用户登录。
- 走查前先跟用户对齐外部平台那半段的操作路径，AI 不熟的平台不自行探索菜单，按用户给的路径走，走不通停下来问。
- 外部平台没有 hac 兜底：配置逻辑全部以用户提供 + 界面实测为准，界面看不到又问不出的标 `[待确认]`。
- **配置来源逐个走通取证**：流程里要填的每个外部平台配置项（ID、密钥、回调地址等），都要在外部平台把获取路径完整走一遍。记下获取页面的链接，从入口到值所在位置逐步截图，值本身打码或用演示值。
- 截图命名和规范不变；写作时交代清楚"现在切到了哪个平台"（如"接下来到企业微信管理后台操作"），读者要能跟上平台切换。
- 外部平台界面里的企业信息、成员名单等敏感内容同样不入图。

## 十、登录与会话

- 账号密码由用户在浏览器窗口自行输入，不代输、不存储（伙伴云和外部平台一样）。
- snapshot 看到登录页说明会话失效：停下来让用户重新登录，再继续。
